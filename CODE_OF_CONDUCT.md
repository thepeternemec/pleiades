# Code of conduct

## The short version

Be straightforward and be kind. Assume the person you are replying to is trying to help.

## What is expected

- **Criticise the code, not the person.** "This will race under concurrent writes" is useful;
  "this is obviously wrong" is not.
- **Say when you do not know.** In this repo especially, a guess presented as a fact is worse
  than an admission of uncertainty, because the docs are what integrators build against.
- **Respect the honesty rule.** Everyone here is asked not to describe the project as more
  finished than it is. Pointing out an overclaim in a doc is a welcome contribution.
- **Be patient with newcomers.** Most people arrive from a search result and have not read the
  architecture doc. "See `docs/ARCHITECTURE.md`" is a fine answer; a link is better.

## What is not acceptable

Harassment, personal attacks, discriminatory language, sustained disruption of a discussion, and
publishing anyone's private information. This applies in issues, pull requests, commit messages,
and anywhere the project is represented.

## Scope

This applies in all project spaces — issues, pull requests, discussions — and when representing
the project in public.

## Enforcement

Report anything that concerns you to the maintainer via a private channel (the email on the
GitHub profile, or a direct message). Reports are read and acted on. Depending on severity, the
response may be a request to edit a message, a warning, or a permanent ban from the project
spaces. Maintainers who do not follow this code will be held to it as well.
